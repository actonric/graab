HOW THIS DOCUMENT WAS BUILT, AND THE TOOL BUG YOU MUST KNOW ABOUT
---------------------------------------------------------------------
Built 2026-09-10/11 by concatenating every live delta doc in this family, in
chronological order, verbatim. Nothing was condensed, deduplicated, reordered,

*** DO NOT USE read_file_content ON THESE DOCS. IT SILENTLY TRUNCATES. ***
The first attempt at this merge used Google Drive's `read_file_content` and 9 of
17 manifest docs came back CUT OFF MID-SENTENCE with no error and no marker. It
is not a size limit: Manifest v11, which is under 4KB, was cut mid-word. That
tool also mangles the text -- it returns a reflowed "natural language
representation" with escaping artifacts (\=====, \[Est.\], \#\#) and
corrupts emoji.


USE `download_file_content` WITH exportMimeType="text/plain" AND BASE64-DECODE
IT. That returns the complete, byte-accurate document. Every read that built
this file was done that way and every one was tail-checked for a natural ending.


Implication worth sitting with: any previous run of this skill that read its own
working docs with read_file_content may have been acting on a partial file
without knowing it. That is a candidate explanation for things this skill has
"forgotten" between runs.

REUSABLE TECHNIQUES LEARNED THIS RUN
=====================================================================
1. IMAGE-ONLY MAILCHIMP NEWSLETTERS ARE NOW FULLY READABLE. This unblocks the
   Apple Tree newsletters permanently. Method:
   a. Get the campaign's "View this email in your browser" mailchi.mp URL from
      the Gmail PLAIN_TEXT body (cheap — no need to pull the 100KB html_body).
   b. Open it in a browser.
   c. Enumerate images with JS, filtering to naturalWidth > 400, and read their
      y-offsets alongside the text headings to work out which image sits under
      which section. The announcements flyer is reliably image index 1, right
      after the masthead; the closures table is the one under "2026 Closures".
   d. To READ one: replace the page body with a single full-width <img>, set
      its src, AWAIT img.decode() PLUS a ~700ms settle, then screenshot. The
      await matters — without it the screenshot captures the previous frame,
      which produced one wrong reading this run before it was caught.
   e. BONUS: from a mailchi.mp page you can same-origin fetch() ANOTHER
      campaign's URL and parse its image list out of the returned HTML. So one
      granted page load gets you every past newsletter's images without
      navigating again. This is how the 08/30 flyer was read.
   Note mcusercontent.com itself remains robots-blocked to fetchers; this is a
   browser-only technique and does not route around robots.




2. Site permission grants in the Claude desktop browser pane are frequently
   one-use even when "site" scope is requested, so each navigation may need a
   fresh request_access. The Chrome extension does not have this friction.
