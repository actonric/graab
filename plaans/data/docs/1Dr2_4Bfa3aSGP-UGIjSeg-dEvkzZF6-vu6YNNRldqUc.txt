mid-document", and that assertion is FALSE — the split is mid-sentence inside source
document 01. CORRECT THIS AT THE NEXT CONSOLIDATION, and do not trust the boundary
claim when reasoning about whether a part is complete.


METHOD NOTE ON READING THE WORKING DOCS FROM A CLOUD RUN, worth keeping:
download_file_content returns base64 in the tool result. Decoding it by hand is not
possible and echoing it back through a shell doubles the context cost. The technique
that works is to hand the read to a subagent with explicit instructions to write the
base64 to a file via a heredoc, decode with `base64 -d`, and grep the decoded text on
disk — the subagent's context absorbs the payload and only the extraction comes back.
Oversized tool results are written to a file by the harness automatically, which is the
cheaper path when it happens; the small docs are the expensive ones, counter-intuitively.

WHATSAPP IMAGE HANDLING — a refinement to the flyer rule, not a change to it.
  The rule says to download_media every image message in a tracked group since the last
  run, because flyers carry their date and venue only in the picture. This run met three
  image messages and resolved all three WITHOUT downloading, on the grounds that each
  shared a sender AND a second-level timestamp with an adjacent text message that fully
  described the item — i.e. they were multi-image classifieds posts, not silent flyers.
  PROPOSED REFINEMENT: download every image whose surrounding context is genuinely
  empty; an image posted in the same second as a describing text message from the same
  sender is a second photo of that item and can be skipped, with the reasoning logged.
  This is offered as a refinement for Richard to accept or reject — the conservative
  reading of the existing rule would have downloaded all three.
