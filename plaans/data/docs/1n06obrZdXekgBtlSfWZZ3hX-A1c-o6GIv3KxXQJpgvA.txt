HOW THIS DOCUMENT WAS BUILT, AND THE TOOL BUG YOU MUST KNOW ABOUT
---------------------------------------------------------------------
Built 2026-09-10/11 by concatenating every live delta doc in this family, in
chronological order, verbatim. Nothing was condensed, deduplicated, reordered,
summarised or "fixed". The only transformation applied was CRLF -> LF.


*** DO NOT USE read_file_content ON THESE DOCS. IT SILENTLY TRUNCATES. ***
The first attempt at this merge used Google Drive's `read_file_content` and 9 of
17 manifest docs came back CUT OFF MID-SENTENCE with no error and no marker. It
is not a size limit: Manifest v11, which is under 4KB, was cut mid-word. That
tool also mangles the text -- it returns a reflowed "natural language
representation" with escaping artifacts (\=====, \[Est.\], \#\#) and
corrupts emoji.


USE `download_file_content` WITH exportMimeType="text/plain" AND BASE64-DECODE
IT. That returns the complete, byte-accurate document. Every read that built
this file was done that way and every one was tail-checked for a natural ending.


Implication worth sitting with: any previous run of this skill that read its own
working docs with read_file_content may have been acting on a partial file
without knowing it. That is a candidate explanation for things this skill has
"forgotten" between runs.


RESOLVING THE FORK
---------------------------------------------------------------------
Two rival chains existed, both descended from the same parent, neither aware of
the other, because SKILL.md hardcoded doc IDs and every scheduled task numbered
its output from those stale pointers:


  CHAIN A, 2026-09-09: Manifest v9 -> v10 -> v11, Source List v10 -> v11,
                       Retention v4 -> v5 -> v6 -> v7
  CHAIN B, 2026-09-10: two independent "v9" Manifests and two independent "v4"
                       Retentions, created hours apart by different tasks


BOTH CHAINS ARE FULLY PRESERVED HERE. Neither was discarded. Where they
disagree, both statements are present, in date order, and the later one does not
silently overwrite the earlier.


Version numbers in this corpus are NOT unique identifiers -- five different
documents are titled "v4" and two are titled "v5". ONLY DRIVE IDs IDENTIFY A
DOCUMENT. Every section below is labelled with its Drive ID for that reason.


SKILL.md has been rewritten to resolve the latest version BY SEARCH rather than
by hardcoded ID, and to treat the title prefix "superseded - " as the only
authoritative marker of non-working state. That is the actual fix; this merge is
the cleanup behind it.

RULE 0 — NEVER DROP A SOURCE.  (Richard, 2026-09-06)
=====================================================================
"Never drop any resource. Track 100% of all sources we've ever found,
but flag appropriately so we know if we should use them or not."




Operational meaning:
1. The source list is APPEND-ONLY. Nothing is ever deleted, condensed,
   summarised, merged, or "cleaned up." Not even dead links. Not even
   duplicates — mark the duplicate, keep both lines.
2. A source that turns out to be useless, dead, hostile, paywalled, or
   spam-infected gets a FLAG, not a deletion. The flag is the value:
   it stops us re-checking it next time.
3. Every new source found in any session is appended the same day it is
   found, before the session ends — even if it produced zero events.
4. When the list is regenerated (Drive update_file cannot change content,
   so a new doc must be created), the old doc is RENAMED "superseded",
   never trashed, and the new doc must contain every line of the old one.
   Count the lines before and after. If the count went down, stop.
5. If a list is ever shortened for readability, say so out loud in chat
   before doing it. Do not make that call silently.

RULE 0 - NEVER DROP A SOURCE.  (Richard, 2026-09-06)
=====================================================================
"Never drop any resource. Track 100% of all sources we've ever found,
but flag appropriately so we know if we should use them or not."




Operational meaning:
1. The source list is APPEND-ONLY. Nothing is ever deleted, condensed,
   summarised, merged, or "cleaned up." Not even dead links. Not even
   duplicates - mark the duplicate, keep both lines.
2. A source that turns out to be useless, dead, hostile, paywalled, or
   spam-infected gets a FLAG, not a deletion. The flag is the value:
   it stops us re-checking it next time.
3. Every new source found in any session is appended the same day it is
   found, before the session ends - even if it produced zero events.
4. When the list is regenerated (Drive update_file cannot change content,
   so a new doc must be created), the old doc is RENAMED "superseded",
   never trashed, and the new doc must contain every line of the old one.
   Count the lines before and after. If the count went down, stop.
5. If a list is ever shortened for readability, say so out loud in chat
   before doing it. Do not make that call silently.

RULE 0 — NEVER DROP A SOURCE.  (Richard, 2026-09-06)
=====================================================================
"Never drop any resource. Track 100% of all sources we've ever found,
but flag appropriately so we know if we should use them or not."




Operational meaning:
1. The source list is APPEND-ONLY. Nothing is ever deleted, condensed,
   summarised, merged, or "cleaned up." Not even dead links. Not even
   duplicates — mark the duplicate, keep both lines.
2. A source that turns out to be useless, dead, hostile, paywalled, or
   spam-infected gets a FLAG, not a deletion. The flag is the value:
   it stops us re-checking it next time.
3. Every new source found in any session is appended the same day it is
   found, before the session ends — even if it produced zero events.
4. When the list is regenerated (Drive update_file cannot change content,
   so a new doc must be created), the old doc is RENAMED "superseded",
   never trashed, and the new doc must contain every line of the old one.
   Count the lines before and after. If the count went down, stop.
5. If a list is ever shortened for readability, say so out loud in chat
   before doing it. Do not make that call silently.

FLAG VOCABULARY — every source carries exactly one USE flag
=====================================================================
[MINED]       Worked. Produced events. Re-check each run.
[PARTIAL]     Worked but not exhausted — known events still unharvested.
[UNTOUCHED]   On the list, never actually opened. Highest-value backlog.
[DRY]         Opened, worked fine, produced nothing relevant to Richard.
              Re-check only seasonally.
[BLOCKED]     Tool/policy refuses it. Not a judgment on the source.
              Sub-reason required: robots / policy / 403 / JS-only / login.
[PAYWALL]     Reachable but costs money or membership to see the calendar.
[COMPROMISED] Serving malware/spam. Do not open. Route around it.
[DEAD]        URL gone or org defunct. Keep the line as a tombstone.
[LEGACY]      Historically useful, no longer publishing. Archive value only.
[NO-URL]      Named by Richard or by a thread, no verified link yet.
[ASK-RICHARD] Only reachable through Richard (private groups, SMS lists,
              logins, physical boards).




Plus an optional QUALITY tier Richard already assigned: A / B / C / Legacy.
Flags describe reachability. Tiers describe worth. Both are kept.

RULE 0 — NEVER DROP A SOURCE.  (Richard, 2026-09-06)
=====================================================================
"Never drop any resource. Track 100% of all sources we've ever found,
but flag appropriately so we know if we should use them or not."




Operational meaning (unchanged from v1-v3):
1. The source list is APPEND-ONLY. Nothing is ever deleted, condensed,
   summarised, merged, or "cleaned up." Not even dead links. Not even
   duplicates — mark the duplicate, keep both lines.
2. A source that turns out to be useless, dead, hostile, paywalled, or
   spam-infected gets a FLAG, not a deletion. The flag is the value:
   it stops us re-checking it next time.
3. Every new source found in any session is appended the same day it is
   found, before the session ends — even if it produced zero events.
4. When the list is regenerated (Drive update_file cannot change content,
   so a new doc must be created), the old doc is RENAMED "superseded",
   never trashed, and the new doc must contain every line of the old one.
   Count the lines before and after. If the count went down, stop.
5. If a list is ever shortened for readability, say so out loud in chat
   before doing it. Do not make that call silently.
