exhausted (check quota)" twice during this run, which cost the budget those ten would have

WHY THE FOLD WAS NOT ATTEMPTED ANYWAY: folding means re-emitting roughly 130KB of text
verbatim through a model's context. That is the single operation in this whole workflow most
likely to silently drop or paraphrase a line, and Rule 0 exists precisely to prevent that.
Doing it having read only 14 of the 25 docs would have been worse than not doing it.


THE ONE THING THAT MAKES THIS SAFE TO DO NEXT TIME, and it does not seem to have been noticed
before: ARCHIVING IS NOT DELETING. The archive subfolder preserves every original. So a fold
that introduces a transcription error is RECOVERABLE — the source doc still exists. That
removes the main reason to be frightened of this job. A run that reads all 25 docs first can
fold and archive safely.


BETTER OPTION, WORTH RICHARD'S CONSIDERATION: this job does not really want an LLM. Exporting
the folder and concatenating the files locally would be byte-exact, instant, and free of
transcription risk entirely. The docs only need to pass through a model's context because
Drive has no upload-from-path tool.

Source List v12's Part 1 ends mid-sentence at "...The Nudge, Goldstar, SF" and Part 2 opens
with a stray fragment "Weekly, SF Bay Guardian, SF Chronicle Pink Section/Datebook)." before
its own header. These join up: "...Goldstar, SF Weekly, SF Bay Guardian, SF Chronicle Pink
Section/Datebook)." So the v12 split was made MID-SENTENCE, contrary to that document's own
claim that "the split is at SOURCE DOCUMENT boundaries, never mid-document". The content is
