RULE 0 — NEVER DROP A SOURCE.  (Richard, 2026-09-06)
=====================================================================
"Never drop any resource. Track 100% of all sources we've ever found,
but flag appropriately so we know if we should use them or not."


1. The source list is APPEND-ONLY. Nothing is ever deleted, condensed,
   summarised, merged, or "cleaned up." Not even dead links. Not even
   duplicates — mark the duplicate, keep both lines.
2. A useless, dead, hostile, paywalled or spam-infected source gets a FLAG, not
   a deletion. The flag is the value: it stops us re-checking it next time.
3. Every new source found in any session is appended the same day it is found,
   before the session ends — even if it produced zero events.
4. When the list is regenerated (Drive update_file cannot change content, so a
   new doc must be created), the old doc is RENAMED "superseded", never trashed,
   and the new doc must contain every line of the old one. Count the lines
   before and after. If the count went down, stop.
5. If a list is ever shortened for readability, say so out loud in chat before
   doing it. Do not make that call silently.

*** RULE 7 — REPORT NEW EVENTS AS A TABLE *** (Richard, 2026-09-09)
=====================================================================
Every run that adds events MUST end its report to Richard with a table of the
newly added events, one row each, with these columns:


  | Event | Category | Date | Time | Source |


  - Event: the title as written on the calendar, emoji and all.
  - Category: the plain-English category the emoji encodes (fair/festival, live
    music, beer & wine, kid programming, food trucks, farmers market,
    comedy/nightlife 21+, park/outdoors, arts, film, school). Multiple allowed.
  - Date: the actual date. For recurring events, state the cadence.
  - Time: start-end. Say so plainly when a time is estimated or unconfirmed.
  - Source: a REAL CLICKABLE LINK to where it was found or verified — the
    organiser's own page wherever possible, not an aggregator, and not a bare
    domain name.


Flag anything needing a ticket, RSVP or registration ABOVE the table, not
buried in it. The table is in addition to, not instead of, the prose summary of
deletions, blockers and what is still unmined.

*** RULE 8 — TWO CHECKS THAT CAUGHT REAL DEFECTS *** (2026-09-09)
=====================================================================
RULE 8a — The duplicate-check window is set by the DATES OF THE EVENTS BEING
  ADDED, not by the search scope. On 2026-09-09 a run searched a 72-hour window,
  grepped only that window for duplicates, then added two events dated 12 and 15
  days out — and created a duplicate of an event already on the calendar.


RULE 8b — Always run a post-write verification pass. Re-fetch everything written
  and check mechanically for: AVAILABILITY_FREE, the exact attribution footer,
  absence of &amp; / &lt; / &gt; anywhere in title, description OR LOCATION, and
  a leading category emoji. One API call. On 2026-09-09 it caught both an
  HTML-escaped footer and the duplicate above.


RULE 8c — A reverse reconciliation (calendar → manifest) is owed and has never
  been done. ~50 master events on the calendar are not in TRACKED and have been
  assumed to be ChatGPT's or Richard's. At least one turned out to be an
  untracked Claude creation, which is what made the duplicate possible. List
  every calendar master not in TRACKED and check its description for the
  "Added by Claude" footer.

FLAG VOCABULARY — every source carries exactly one USE flag
=====================================================================
[MINED]       Worked. Produced events. Re-check each run.
[PARTIAL]     Worked but not exhausted — known events still unharvested.
[UNTOUCHED]   On the list, never actually opened. Highest-value backlog.
[DRY]         Opened, worked fine, produced nothing relevant. Recheck seasonally.
[BLOCKED]     Tool/policy refuses it. Not a judgment on the source.
              Sub-reason required: robots / policy / 403 / JS-only / login / no-device.
[PAYWALL]     Costs money or membership to see the calendar. SEE RULE 6 FIRST.
[COMPROMISED] Serving malware/spam. Do not open. Route around it.
[DEAD]        URL gone or org defunct. Keep the line as a tombstone.
[LEGACY]      Historically useful, no longer publishing. Archive value only.
[NO-URL]      Named by Richard or a thread, no verified link yet.
[ASK-RICHARD] Only reachable through Richard (private groups, SMS lists,
              logins, physical boards). NOW ACTIVELY USED — see the roster doc.
