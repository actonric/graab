The <select> element can now be customized with CSS

Every dropdown on this page is a real, native <select>. No JavaScript widget, no ARIA re-implementation, no <div> soup. In browsers that support appearance: base-select the button, the picker, the options and the checkmark are styled with plain CSS. Everywhere else you get the browser's built-in control.

✅ Your browser supports appearance: base-select. The selects below are fully customized. ℹ️ Your browser does not support appearance: base-select yet. You are seeing the native fallback, which is the whole point: the markup degrades gracefully.

1. Opt in with two declarations

Set appearance: base-select on the <select> and on its ::picker(select) pseudo-element. From that point on, the button and the popover are ordinary boxes you can style. 

select,
select::picker(select) {
  appearance: base-select;
}

2. Rich content inside options

Options may now contain real HTML: images, inline SVG, spans, secondary text. Put a <button> with a <selectedcontent> element first in the select and the browser mirrors the chosen option's markup into the button for you. 

<select class="graab">
  <button>
    <selectedcontent></selectedcontent>
  </button>
  <option value="pear">
    <span class="icon">🍐</span>
    <span class="text">
      <span class="name">Pear</span>
      <span class="desc">Sweet, grainy</span>
    </span>
  </option>
  …
</select>

The description line is hidden inside the button with selectedcontent .desc { display: none }, so the closed control stays compact.

Selected value: apple

3. Inline SVG and images

Because options are just flow content, an assignee picker with avatars needs zero JavaScript. Inline SVG avatars here; <img> works the same way. Grouping with <optgroup> and disabled options still work. Add a <legend> as the first child of a group to get a styleable label; the label attribute stays as the accessible name and the fallback. 

select.graab option {
  display: flex;
  align-items: center;
  gap: .6rem;
}
select.graab option::checkmark {
  order: 1;                 /* push it to the end */
  margin-inline-start: auto;
  content: "✓";
}

4. Animate the picker open and closed

The picker is a popover in the top layer, so it animates like one: @starting-style for the entry, transition-behavior: allow-discrete so display and overlay wait for the exit, and the :open pseudo-class to rotate the ::picker-icon. 

select.graab::picker(select) {
  opacity: 1;
  translate: 0 0;
  transition: opacity .18s, translate .18s,
              display .18s allow-discrete,
              overlay .18s allow-discrete;
}
select.graab:not(:open)::picker(select) {
  opacity: 0;
  translate: 0 -.35rem;
}
@starting-style {
  select.graab:open::picker(select) {
    opacity: 0;
    translate: 0 -.35rem;
  }
}
select.graab:open::picker-icon {
  rotate: 180deg;
}

5. Side by side with the native control

Same markup, one without the class. The unstyled one is what every select on this page looks like in a browser without support, and what mobile users may still prefer. appearance: base-select is opt-in per element, so you can adopt it gradually. 

@supports (appearance: base-select) {
  /* progressive enhancement lives here */
}

Things worth knowing

  • Keyboard and screen readers keep working. It is the same element with the same semantics, so arrow keys, type-ahead, form submission and validation are untouched.
  • The picker is anchored by default. It uses CSS anchor positioning, flips to stay on screen, and inherits the button's width. You can override it with position-anchor, position-area and friends.
  • Interactive content inside options is not allowed. Links, buttons and inputs inside an <option> are ignored on purpose.
  • Parser rules changed. Chrome 135 relaxed the HTML parser so <button>, <span>, <img> and <svg> survive inside a select. Older parsers strip the tags and keep the text, which is exactly the fallback you want.
  • Support: Chromium 135+ (Chrome, Edge, Opera, Brave). Firefox and Safari fall back to the native control. Check CSS.supports("appearance", "base-select") at runtime.
